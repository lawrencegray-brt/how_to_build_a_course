# Rubrics — What "Done" Looks Like

*Each deliverable is judged against a **completion checklist** — met / not-yet, not a letter grade. **Not-completed means not-yet:** you get specific feedback and revise until it meets the bar, with no penalty. Rows marked **(must)** are required. Keep this beside you and self-check before you submit.*

## Rubric 5.1 — Course + Module Objectives (Deliverable A)

| Criterion | Meets standard |
| --- | --- |
| Measurable | Uses Bloom action verbs; no "understand/know/appreciate." |
| Student-focused | Describes what the *student* can do, not what the instructor provides. |
| Right altitude | Aimed at the highest level the content honestly supports (Apply/Analyze/Create for a skills course). |
| Laddered | Module objectives clearly roll up to course objectives. *(Course objectives come Week 1; module objectives Week 2, once you have modules.)* |
| Assessable | You could write a test item or task directly from each objective. |

## Rubric 5.2 — Master Design Document (Deliverable B)

| Criterion | Meets standard |
| --- | --- |
| Complete | Every module has objectives, topics, readings, activities, assessments. |
| Mapped | Each module objective traces to a course objective. |
| Practice + feedback | Every module includes a way to practice *before* being assessed. |
| Values mapped | Each value from your Decisions doc is mapped to a **concrete feature** of the course — not restated. "Meet people where they are" becomes "hints remind of purpose, never hand over the answer." |
| Coherent sequence | Concepts build on each other; prerequisites are explicit. |
| Practices audited *(must)* | The seven-practices audit was run; each gap found became a design task addressed in the MDD. |

## Rubric 5.3 — One Complete Module, Built and Taught (Deliverable C)

Judged in **two parts** — an **artifact review** of your module folder, plus the **live teach-back** in Week 5.

**Artifact review — from your module folder:**

| Criterion | Meets standard |
| --- | --- |
| Three packages present *(must)* | Instructor materials, student materials, and a teaching guide all exist (to the minimum-viable floor). |
| Scaffolded *(must)* | Student practice uses appropriate fill-in/TODO support, not blank pages. |
| Correct *(must)* | Any code/worked examples run and were verified, not just plausible. |
| AI-direction + verification log *(must)* | A short log shows what you asked GenAI for, what it got wrong, and how you caught and fixed it. |
| Accessible *(must)* | Offers more than one way in across UDL's three principles — represent / engage / show mastery — not color-alone. |
| Evaluate-&-improve plan *(must)* | A short plan appraises the course against evaluation criteria and names improvements for the next run. |
| Visual | Uses visualization where it aids understanding. |
| Self-assessment | Includes a way for students to gauge their own understanding. |
| Answer space bounded *(if open-ended)* | For divergent assessments, the range of valid answers was charted ahead (by bounding the answer space, §6a step 5b) — used to *widen* the feedback envelope, not define it. |

**Live teach-back — Week 5:**

| Criterion | Meets standard |
| --- | --- |
| **Portable (the key test)** *(must)* | A different instructor could teach it from the guide alone — demonstrated by the teach-back. |
| Teach-back delivery *(must)* | The 10-minute segment was clear, on-time, followed your own teaching guide, and applied the Teaching It Well principles. |
